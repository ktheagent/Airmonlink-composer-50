## Not deleted

Underlying engine methods are preserved because many have useful tested semantic logic. They are not exposed as completed production features until the corresponding corrective build supplies:

- correct staff interaction;
- context-sensitive availability;
- semantic mutation;
- one undo/redo transaction;
- visible layout result;
- save/reopen proof;
- Staff/Sol-fa and part synchronization where applicable;
- automated and manual evidence.

## Required future removals

Any command that still fails its scheduled corrective build must remain hidden or be deleted. It must not be re-enabled merely because a unit test exists.
